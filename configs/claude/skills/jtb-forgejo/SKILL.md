# Reference
All our code is in a self-hosted Forgejo instance at `git.jtbatesgroup.com`. 

### Creating PRs

Create a PR markdown file in `docs/prs` as .{branch-name}.md with the .PR_FORMAT.md,
then use the `fj` CLI to create a PR using the --body-file flag pointed at the new PR md.
If the directory does not exist, create it. If `.PR_FORMAT.md` does not exist in that directory,
create it with the following: 
```markdown
# Quick Description
-- short two line summary of what changed --
## Problem
-- the problem or request that started this work --
## The Fix
-- what was changed and why --
## Tests
-- how to test the changes, either in the frontend or the xUnit tests
## Schema Changes
-- any schema changes --
## Configuration Changes
-- any configuration changes --
```

The command to create a new PR looks like the following:
`fj pr create "{pr title} --base main --head {branch-name} --body-file {new pr md}"`
Once the PR is created, return to me the `fj` command to view it in the browser:
`fj pr browse {pr number}`

## Adding Comments to PRs

To add a comment to the PR, use the following command:
`fj pr comment [PR#] {comment info}`

## Linking Issues to PRs

If there is any issue that matches the work the PR is doing, add a comment in the PR
in form of: `Fixes {org}/{repo}#[issue number]`.

## Rules

- Always assume the `--base` should point at main, unless otherwise specified.
- Do not apply any labels or assignees, and do not request any reviewers.
- Do not include any "created by"/"generated by"/"co authored by" sections to reference yourself
